# Test mit dem größten passenden lokalen Modell

**Ergebnis: erfolgreich.** Ein echter K2-Modelllauf erzeugte das Flask-Backend und
korrigierte es nach Fehlerfeedback, bis alle zwölf Vertragsprüfungen bestanden.
Geprüft wurden unter anderem alle 1001 Fibonacci-Indizes von 0 bis 1000.

| Messung | Ergebnis |
|---|---:|

| Modellaufrufe | 5 |

| Tool-Aufrufe / Iterationen | 8 / 13 |
| Tokens einschließlich Reasoning | 11.351 |
| Verifikations-Exit-Codes | 1 → 1 → 0 |
| GPU-Spitzenbelegung, alle Prozesse, 200-ms-Abtastung | 6.784 MiB von 10.240 MiB |
| GPU-Modellschichten | 37/37 |
| Modellgewichte / KV-Cache auf CUDA0 | 5.322,23 / 1.152,00 MiB |

Die erste Implementierung bestand 11/12 Testmethoden. Sie scheiterte an einer
Eingabe mit 5000 führenden Nullen, weil Python die direkte Integer-Konvertierung
so langer Strings begrenzt. Eine abgeschnittene, mehrfach wiederholte Dateiausgabe
wurde vom Parser verworfen. Nach weiterem Fehlerfeedback erzeugte das Modell selbst
eine Korrektur: führende Nullen entfernen und signifikante Stellen vor `int()` begrenzen.
Der Anwendungscode wurde nicht von Hand geändert.

Der [generierte Code](results_rtx3080/app.py), [Messdaten](results_rtx3080/results.json),
Modellantworten, Observations und GPU-Verlauf liegen unter [results_rtx3080](results_rtx3080/).
Dies ist ein einzelner Entwicklungsrun, kein kontrollierter Modellvergleich.
Der Backend-Adapter liegt ausschließlich beim Beispiel; der Runtime-Core blieb unverändert.

## Backend und Wiederholung

Das Modell benötigt eine besondere llama.cpp-Variante. Die bereits installierte
Version b10362 meldete `unknown model architecture: 'k2-horizon'`. Der Hersteller
verweist auf seinen [K2Horizon-Fork](https://github.com/MBZUAI-IFM/llama.cpp/tree/model/K2Horizon).
Für den Test wurde Commit `35999d101cf2233fc54f09c3c8d599da7303ce02` mit CUDA für
Compute Capability 8.6 gebaut.

Der lokale Build verwendete den vorhandenen CUDA-12.9-Compiler und GCC 14.
Für die neuere Host-glibc wurden in einer privaten Toolkit-Kopie die sechs
Deklarationen `cospi`, `cospif`, `sinpi`, `sinpif`, `rsqrt`, `rsqrtf` mit `noexcept(true)`
angeglichen. OpenMP wurde wegen eines inkompatiblen statischen Host-Linkers deaktiviert.
Andere Projektinstallationen blieben unverändert.

Beispiel mit einem kompatiblen lokal gebauten Server:

```bash
/path/to/llama-server \
  --model /path/to/K2-Horizon-7B-Q4_K_M.gguf \
  --device CUDA0 --gpu-layers 999 --override-tensor '.*=CUDA0' \
  --split-mode none --fit off --ctx-size 8192 --parallel 1 \
  --batch-size 512 --ubatch-size 128 --flash-attn on \
  --host 127.0.0.1 --port 18089 --no-webui --reasoning-budget 1024 --verbosity 4

python examples/fibonacci_flask/gguf_demo.py \
  --model /path/to/K2-Horizon-7B-Q4_K_M.gguf \
  --revision a5094087a5a55c2de80264c11504d8ca95a022ff
```

Bei einem CUDA-Toolkit außerhalb der Systempfade muss dessen `lib64` im
`LD_LIBRARY_PATH` liegen, sowohl beim Linken des Servers als auch beim Start.

`--override-tensor` legt auch die sonst auf der CPU verbleibenden Eingabe-Embeddings
auf die GPU. Der tatsächliche Speicherverbrauch muss zusätzlich im Serverlog und
über `nvidia-smi` geprüft werden. `--fit off` verhindert automatische Anpassungen.

[gguf_demo.py](gguf_demo.py) enthält einen kleinen, expliziten `ModelBackend`-Adapter
für diesen lokalen Test. Er prüft den Modellpfad, zählt den Prompt vor der Inferenz
und übernimmt gemessene Tokens einschließlich Reasoning. Es werden keine nativen
Tools oder JSON-Ausgaben vom Modell verlangt. Parser, Gates und die zwölf vorhandenen
Flask-Vertragsprüfungen bleiben aktiv. DSPy-Prompts aus den 0.5B-Experimenten werden
bei diesem Modelltest nicht verwendet.

Ein unterbrochener laufender Run kann über dasselbe Skript mit `--resume runs/RUN_ID`
und identischem Server fortgesetzt werden. Die allgemeine CLI verwendet weiterhin
den Transformers-Adapter; sie ist für diesen GGUF-Test nicht der Resume-Einstieg.

Der Versuch begrenzt den Gesamtkontext auf 8192, die einzelne Ausgabe auf 4096 Tokens
und Reasoning serverseitig auf 1024 Tokens. Das sind praktische lokale Runtime-Limits,
keine Reproduktion der Hersteller-Benchmarks mit mindestens 32768 Ausgabetokens.
